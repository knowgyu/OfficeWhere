# Word 쪽 단위 비교 검토 메모

## 배경

버전 관리에서 PPT는 슬라이드 단위로 변경점을 보여주면 사용자가 이해하기 쉽다. Word도 사용자 관점에서는 “문단/표”보다 “몇 쪽에서 무엇이 바뀌었는지”가 더 자연스럽다.

## 현재 한계

DOCX 내부 구조는 PPT의 슬라이드나 Excel의 셀처럼 페이지가 고정 단위로 저장되지 않는다. Word 문서는 기본적으로 흐르는 본문이며, 실제 쪽 번호는 Word/LibreOffice 같은 렌더링 엔진이 글꼴, 여백, 줄간격, 표/이미지 크기, 프린터/레이아웃 환경 등을 반영해 계산한다.

현재 구현은 명시적 페이지 나눔과 일부 저장된 페이지 나눔 힌트를 이용해 가능한 경우 쪽 번호를 표시한다. 따라서 정확한 “사용자가 보는 쪽”이라기보다는 best-effort 표시다.

## 고려 가능한 방향

1. 현재 방식 유지
   - 장점: 빠르고 가볍다. 별도 렌더링 의존성이 없다.
   - 단점: 실제 Word 화면의 쪽 번호와 다를 수 있다.

2. LibreOffice headless 등으로 PDF 변환 후 페이지 단위 비교
   - 장점: 실제 A4 렌더링 기준에 가까운 쪽 단위 비교가 가능하다.
   - 단점: 변환 시간이 들고, 배포 용량/환경 의존성/오류 처리가 늘어난다. 네트워크 드라이브 문서 처리 시 체감 속도도 나빠질 수 있다.

3. 1차는 문단/표 기반 변경 내용을 더 읽기 쉽게 유지하고, “정확한 쪽 단위 비교”는 고도화 과제로 분리
   - 장점: 현재 제품 안정성을 유지하면서 사용자 피드백을 더 받을 수 있다.
   - 단점: 사용자가 기대하는 “몇 쪽 변경” 경험은 아직 제한적이다.

## 임시 결론

Word의 정확한 쪽 단위 변경 관리는 추가 검토가 필요하다. 당장은 현재 best-effort 쪽 표시를 유지하되, 향후 PDF/렌더링 기반 비교를 도입할지 별도 설계 후 결정한다.
