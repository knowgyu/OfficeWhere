# OfficeWhere v0.14.2 release notes

## Search latency and modified-date visibility

- Query search no longer globally sorts matched content files by latest modified time. This removes the expensive newest-first ordering path that could make common searches feel slow on large libraries.
- Search results still include each file's `file_mtime`, and the search UI now shows a concise Korean `수정 <날짜>` label beside result paths when the value is known.
- The no-query “전체 문서” landing list still uses the existing recent-document listing path; this patch targets queried search results.

## Faster rescan mtime checks on Windows

- When the Windows Everything SDK is available, OfficeWhere now requests date-modified metadata together with discovered file paths.
- Library rescan can use trusted Everything-provided mtimes to skip unchanged existing files without repeating the rescan-stage `os.stat` mtime check.
- Everything remains optional and never authoritative: missing/invalid metadata, unavailable SDK, non-Windows environments, and untrusted candidates fall back to the existing filesystem stat path.
