# OfficeWhere v0.15.2

검색 요청마다 반복되던 SQLite DB open 고정비를 줄이는 패치 릴리즈입니다.

## 성능 개선

- 검색 전용 persistent read connection을 도입했습니다.
- 앱 시작 후 prewarm 또는 첫 검색에서 검색 DB connection을 열고, 이후 반복 검색은 같은 app-owned SQLite read connection을 재사용합니다.
- EDR/백신 환경에서 cache miss 검색마다 `db_open_ms`가 약 2.7초씩 반복되던 상황을 줄이는 것이 목적입니다.

## 안정성 처리

- DB write, rescan, 파일 등록/삭제/mtime 갱신, 인덱스 repair, DB path 변경, schema 초기화, backend 종료 시 persistent read connection을 명시적으로 닫고 다음 검색에서 새로 열도록 했습니다.
- 검색 중 connection이 닫히지 않도록 process-local lock으로 borrow 구간을 보호합니다.
- 원본 Office 문서는 계속 읽기 전용으로만 처리합니다.

## 진단 로그

- 검색 로그에 connection 재사용 상태를 구분하는 필드를 추가했습니다.
  - `db_connection_source`: `persistent_opened` 또는 `persistent_reused`
  - `db_connection_reused`
  - `db_connection_generation`
  - `db_connection_invalidated`
  - `db_connection_invalidate_reason`
- 정상 기대값은 첫 open/prewarm 이후 반복 검색에서 `db_connection_source=persistent_reused`, `db_open_ms=0`에 가까운 상태입니다.

## 검증

- 반복 cache miss 검색이 persistent read connection을 재사용하는 회귀 테스트를 추가했습니다.
- write/rescan 계열 invalidation 후 다음 검색이 새 connection을 열고, 그 다음 검색부터 다시 재사용되는지 검증했습니다.
- `configure_database()`와 수동 close가 열린 connection을 해제하는지 검증했습니다.
- startup prewarm 이후 첫 cache miss 검색이 warmed connection을 재사용하는지 검증했습니다.
