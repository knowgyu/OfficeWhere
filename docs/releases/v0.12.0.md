# OfficeWhere v0.12.0 release notes

## Windows app data location change

- Packaged Windows launches now use `%LOCALAPPDATA%\OfficeWhere` as the canonical Electron `userData` directory instead of Electron's default `%APPDATA%\OfficeWhere` Roaming profile.
- This is a breaking storage path change: existing data left under `AppData\Roaming\OfficeWhere` is now legacy and is not the active OfficeWhere profile for v0.12.0+.
- `provider-discovery.json`, `backend-data`, logs, settings, and Chromium session/cache data now follow the LocalAppData-backed `userData` path on normal Windows launches.
- Launches that explicitly pass `--user-data-dir` are still respected. This keeps E2E Playwright fixtures and other isolated profiles from writing to the real user profile.

## Safety

- E2E backend startup guards now reject both current `AppData\Local\OfficeWhere` and legacy `AppData\Roaming\OfficeWhere` real-user data paths.
- Non-Windows app data behavior is unchanged.

## Verification checklist

- `cd frontend && npm test -- --run src/electronAppPaths.test.ts`
- `./venv/bin/python -m pytest -q tests/test_e2e_guard.py`

- `cd frontend && npm run build`
