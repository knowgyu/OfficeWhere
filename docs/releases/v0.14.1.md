# OfficeWhere v0.14.1 release notes

## Backend startup reliability

- Packaged Electron now checks startup readiness with the lightweight `/api/health?startup=1` endpoint so large app-owned databases do not make startup depend on derived index status reads.
- The per-probe startup health timeout was increased to 10 seconds while preserving the existing large-data overall startup budget.
- Backend startup logs now record the selected dynamic port, health URL, probe timeout, overall startup budget, pending probe reason, successful readiness, final timeout, retry scheduling, stop requests, and whether process exit was expected.
- Provider discovery publishing is now best-effort; a discovery-file write failure is logged but no longer blocks an otherwise healthy backend startup.

## Why this patch exists

The failure mode could look like `backend exited signal=SIGTERM` even while backend logs contained repeated `GET /api/health ... 200 OK`. In that case Electron was the process sending SIGTERM after its startup readiness loop timed out. The new log lines make that distinction explicit: expected shutdowns include `expected=true`, startup probe failures include `backend health pending`, and real startup timeout includes `backend health startup timed out` with the last probe reason.
