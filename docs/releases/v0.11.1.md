# OfficeWhere v0.11.1 release notes

## Provider runtime discovery

- Packaged Electron now writes `<userData>/provider-discovery.json` after the dynamic backend passes health checks.
- The discovery file identifies `OfficeWhere`, contract `v1`, app version `0.11.1`, `/api/provider/v1` endpoint URLs, backend pid, and generated/updated timestamps.
- Writes are atomic via temp file + rename. Clean shutdown removes only the discovery document owned by the current Electron/backend process identity.
- External consumers must treat the file as stale unless the PID is alive and `/api/provider/v1/health` plus `/api/provider/v1/manifest` agree with the discovery metadata.

## Safety

- No new state-changing provider endpoints were added.
- Source Office documents remain read-only; discovery contains only local endpoint metadata and no document contents or secrets.

## Verification checklist

- `./venv/bin/python -m pytest -q tests/test_provider_contract.py`
- `cd frontend && npm test -- --run`
- `cd frontend && npm run build`
- `cd frontend && npm run build:electron`
- `cd frontend && npm run package:win` where local platform/runtime support allows
