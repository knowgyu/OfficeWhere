# OfficeWhere v0.14.4 release notes

## What changed

- Search now writes one request-level `search_request_done` performance log with `request_id`, cache status, filename/content/merge timings, Everything fallback reason, and result counts.
- Filename search can use Windows Everything SDK as an optional candidate accelerator, while registered OfficeWhere DB rows remain authoritative for filters, ordering, pagination, and returned results.
- Search responses are cached briefly in memory and invalidated after document registration, indexing/chunk writes, mtime updates, delete/prune actions, reindex, and library rescan completion.

## Notes

- Everything acceleration is optional. Non-Windows, disabled, unavailable, oversized, or unsupported filename queries fall back to the existing DB filename search.
- Source documents remain read-only; this patch only changes app-owned search/log/cache behavior.
- Frontend package and backend API version: `0.14.4`.
