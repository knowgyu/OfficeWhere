# OfficeWhere v0.15.0

검색 성능을 중심으로 다듬은 마이너 릴리즈입니다.

## 개선 사항

- 검색 요청 1회 안에서 검색 인덱스 상태 확인, 파일명 검색, 본문 FTS 검색이 하나의 SQLite 읽기 연결을 공유하도록 개선했습니다.
- backend 시작 직후 SQLite/FTS 검색 저장소를 가볍게 prewarm해 첫 검색에서 발생하던 초기 DB 접근 지연을 줄였습니다.
- 회사 EDR/실시간 보안 검사 환경에서 SQLite 연결을 여러 번 열며 누적되던 지연을 줄이도록 검색 경로를 정리했습니다.
- Everything 후보 기반 파일명 검색 경로와 기본 DB fallback 경로 모두 기존 결과 권한/정렬을 유지하면서 동일한 읽기 연결을 재사용합니다.

## 안전성

- API 요청/응답 형식은 변경하지 않았습니다.
- 원본 Office 문서는 계속 읽기 전용으로만 처리합니다.
- 검색 캐시, 파일 타입 필터, 페이지네이션, 인덱스 stale 처리 동작은 기존과 동일하게 유지했습니다.

## 검증

- 검색 회귀 테스트에 cache miss 검색 요청이 SQLite 읽기 연결 하나만 사용하는지 확인하는 케이스를 추가했습니다.
- startup prewarm이 주요 검색 테이블을 읽기 전용으로 건드리는지 확인하는 회귀 테스트를 추가했습니다.
- Everything 후보 경로와 borrowed connection 소유권/row 호환성 회귀 테스트를 추가했습니다.
